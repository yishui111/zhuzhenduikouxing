# 真人关键帧表情合成（主方案：真人关键帧拼接）

> 项目：light-avatar ｜ 2026-08-16 决策关键帧路线；2026-09-05 起为本项目**唯一方案**（原 3D blendshape 备选方案及其模型/文档已按用户要求移除）
> 一句话：**录一段真人说话视频 → 抽帧打标成"关键帧/状态片段库" → 运行时用声学特征（能量/F0/语速）选帧拼接 → 实时合成"这个人在说话"的视频**。
> 效果定位：**真人级观感**（拼接的是真人录像，不是 3D 模型）；代价是**一人一录**、**换皮能力暂缓**（换皮=换人重录）。

> **📌 实际实现简化说明（2026-08-16 用户确认）**：开发中按用户实测反馈简化了流程——**废弃"8 段录制脚本 + 喊记号 + 分段打标"流程**（用户用不上），实际产品流程为：
> **上传说话视频 → 建库工具一键生成"嘴巴张开弧度"帧序列（能量分位近似）→ 主页面用"能量范围 → 图片"绑定控制**（可配置能量下限/上限/防闪回）。
> 本文档"录制规范/记号检测/分段打标/状态机防抖"等小节为早期设计，保留作参考；以 README 与代码为准。

## 一、为什么是这个方案（痛点与先例）

3D blendshape 路线有两个客观短板（本项目因此不采用）：
1. **观感**：3D 低模是"动画级表情"，与"真人级"期望有落差；
2. **资产**：免费且带全套 blendshape 的人头极难找（实测 three.js 官方 LeePerrySmith GLB 无 morph target）。

本方案直接绕开这两点：**用真人录像当"素材库"**，观感天然真人级，资产=自己录一段视频（完全可控）。

**这不是野路子，是有成熟先例的"采样式表情合成"（concatenative / sample-based facial animation）：**

| 先例 | 做法 | 借鉴点 |
|------|------|--------|
| [Video Rewrite（Bregler et al., SIGGRAPH 1997）](https://www.semanticscholar.org/paper/Video-rewrite%3A-visual-speech-synthesis-from-video-Bregler-Covell/faef9e9470840eaa0f4e292a09fd4f8b8695d9d0) | 录说话视频 → 按语音单元挑帧段拼接 → 段边界交叉淡化 | 片段级拼接 + 段间淡化（本方案改用"声学特征"做选帧准则，不做内容理解） |
| [Reallusion CrazyTalk / Cartoon Animator](https://manual.reallusion.com/CrazyTalk_Animator_2/ENU/Pro_and_Std/08_Animation/Facial_Puppeteering/Facial_Clips_and_Keys.htm) | 2D 口型关键帧 + 音频自动放置关键帧 + 自动生成中间过渡 + 可手动微调 | 口型轨道与表情轨道分离；自动关键帧+人工微调；灵敏度参数 |
| [Reallusion Motion LIVE 2D](https://manual.reallusion.com/motion-live-2d/cta/facial-mocap/recording-audio-and-lipsync-animation.htm) | 音频驱动口型动画，带 **Sensitivity（灵敏度）** 调节 | 灵敏度/强度做成用户可调参数 |
| [Live2D 动态同步（Motion-sync）](https://docs.live2d.com/zh-CHS/cubism-editor-manual/motion-sync/) | 音频 RMS 能量 → 嘴部参数，强度可调、平滑 | 能量→开合映射 + 平滑 + 参数面板 |
| [VTubeStudio 唇音同步](https://github.com/rubujo/VTubeStudio/wiki/%E5%94%87%E9%9F%B3%E5%90%8C%E6%AD%A5) | 能量→嘴开合，灵敏度/平滑可调 | 同上，行业标配 |

**本方案与上述产品的差异**：商用产品大多面向"创作者手动调整"（时间轴编辑），本方案目标是**纯实时、零人工干预**的网页应用——素材库在录制阶段一次性做好，运行阶段全自动。

## 二、总体架构（管线）

```
① 录制（M0）           ② 预处理与建库（M1）         ③ 运行时驱动（M2/M3）            ④ 输出
固定机位录像            抽帧 → 脸对齐 → 裁切           音频(文件/麦克风)                   实时预览
按脚本分段表演          打标签(能量档×表情档×过渡)      → 特征提取(能量/F0/语速)           录屏导出
每段喊记号              → 关键帧/状态片段库             → 档位映射 → 状态机(防抖)          (M3)
                        (manifest.json)              → 选帧/片段 + 交叉淡化 → 画布合成
```

**关键点：全程无神经网络推理。** 运行时只有"算特征（几毫秒）+ 按标签选图 + Canvas 2D 画两帧做淡化"，连 WebGL 都不需要。

## 三、M0 录制规范（素材质量 = 效果上限，必须按规范录）

### 3.1 录制环境 checklist（不满足就重录，别将就）

- [ ] 机位固定：相机/手机放稳，全程不动（可用支架），画面只含人物脸部~肩部
- [ ] 光线固定：自然光或台灯，**不要**忽明忽暗；脸部无强烈阴影
- [ ] 背景干净单一：纯色墙/窗帘，避免杂乱和走动的人
- [ ] 人物头部尽量不动：下巴可轻靠固定物（枕头/书），**表情范围放开**（嘴要能张大、能笑、能挑眉）
- [ ] 分辨率 ≥720p、帧率 ≥30fps、时长 1~2 分钟、文件 mp4/webm
- [ ] 录前试录 10 秒，播放检查：脸部清晰、无抖动、无过曝

### 3.2 录制脚本（按"档位"分段表演，每段开头喊一个记号便于自动打标）

| 段 | 表演内容 | 记号（喊出口） | 对应标签 |
|----|----------|----------------|----------|
| 1 | 闭嘴、中性表情，说 2~3 句平缓的话 | "一" | 能量档0 × 中性 |
| 2 | 嘴微张说话（正常音量） | "二" | 能量档1 × 中性 |
| 3 | 嘴中张说话（音量稍大） | "三" | 能量档2 × 中性 |
| 4 | 嘴大张说话（放开发音） | "四" | 能量档3 × 中性 |
| 5 | 微笑着重复 2、3（嘴微张/中张） | "五" | 能量档1~2 × 微笑 |
| 6 | 挑眉/惊讶表情重复 3、4 | "六" | 能量档2~3 × 挑眉 |
| 7 | 每档之间做一次"闭→张→闭"的慢动作（供过渡片段库） | "过" | 过渡片段 |
| 8 | 收尾：保持闭嘴中性 3 秒（供静音/初始帧） | "收" | 能量档0 × 中性 |

> 打标逻辑：**录的时候分段，比事后逐帧标省力一个量级**。分段时间轴由记号音频自动切分，M1 建库时人工校对微调即可。

## 四、M1 预处理与素材库构建

### 4.1 管线步骤

1. **抽帧**：按 30fps 抽取，人脸区域裁切为统一 512×512（输出 JPEG 质量 80，单帧约 30~60KB）。
2. **脸对齐（推荐做，消除重影的关键）**：用 MediaPipe FaceMesh 检测每帧双眼/鼻 landmark → 仿射变换把脸"钉"到统一位置、统一尺度再裁切。这样任意两帧的脸都重合，交叉淡化不会"双重曝光"。
   - MVP 兜底：录制时头不动 + 不启用对齐，直接按固定框裁切（脸会轻微漂移，淡化略糊但可用）。
3. **背景处理**：背景用一张固定帧（录制第 1 帧或人工选），脸部区域叠加到固定背景上 → 背景永不闪烁。（MVP 可先整帧裁切，背景本来就固定。）
4. **切片与打标**：按录制脚本记号切分时间轴 → 每段内取"稳定代表帧"作为静态关键帧，段内相邻帧抽 3~6 帧组成过渡片段 → 自动打初始标签 → 人工校对界面微调（删掉眨眼/表情失控的帧）。
5. **输出素材库**（见 4.3 结构）：manifest.json + frames/ + clips/。

### 4.2 标签体系（素材项 = 三要素）

```
{ 类型:   静态帧 | 过渡片段
  嘴档:   E0闭嘴 | E1微张 | E2中张 | E3大张
  表情档: 中性 | 微笑 | 挑眉
  附加:   片段帧数/源时间段/备用标记 }
```

- 静态帧：每 (嘴档 × 表情档) 组合至少 1 帧，共约 12 帧（对应录制脚本 1~6 段）；
- 过渡片段：E0→E1、E1→E2、E2→E3 及反向（反向可复用同片段倒放），微笑渐强/弱；对应脚本第 7 段；
- 备用帧：每组合多取 2~3 个候选，运行时同档位内随机/轮换，增加自然感（避免"同一张脸反复出现"的重复感）。

### 4.3 素材库文件结构（皮/骨分离思路的 B 版：人=骨，风格=皮）

```
avatar/
└── libs/                       # 一人一套"关键帧库"
    └── lib_default/            # 默认人物（录制样片）
        ├── manifest.json       # 标签索引（关键帧+片段清单）
        ├── frames/             # 静态关键帧 E0~E3 × 表情（JPEG 512×512）
        └── clips/              # 过渡片段（帧序列子目录）
```

> 换皮暂缓。若未来要做"风格化皮"：对全部帧离线套统一滤镜（动漫/素描预设），生成新的 lib_xxx/，运行时加载不同库即可——运行时零成本。

## 五、M2 运行时驱动引擎（核心：状态机 + 防抖三件套）

### 5.1 特征提取（纯计算模块，Node 可测）

| 特征 | 采样 | 驱动目标 |
|------|------|----------|
| RMS 能量（dB） | 10ms 帧 | 嘴档 E0~E3 |
| F0 基频（M3 接入） | 30ms 帧 | 表情档（中性/微笑/挑眉） |
| 元音共振峰 F1/F2（2026-09-05 接入，见 5.4） | 每 2 帧（≈33ms，对齐 AIRI 口型线 32ms 帧思路） | 元音嘴型（a/e/i/o/u） |
| 语速/过零率（M3） | 100ms 级 | 眨眼/点头频率（M4） |

自适应归一化：3s 滑动窗口 95 分位作 E_max、-50dB 作 E_min（保证任何音量/任何人嘴型幅度一致）。

### 5.2 状态机（防抖是成败关键，以下三条缺一不可）

```
当前状态 = (嘴档, 表情档)
每帧：计算目标档位 → 与当前状态比较
1. 滞回（Hysteresis）：目标档位变化量 < 阈值（如 <0.15 档）→ 不切换，防毛刺
2. 确认：目标档位连续稳定 N 帧（如 3 帧 ≈ 30ms）才触发切换，防单帧脉冲（爆破音 p/b/t）
3. 状态保持：切换后新状态至少停留 100ms，防"嘴高频抖动"（对比：商用产品同样靠关键帧驻留+过渡）
切换执行：
  优先：有同表情档的过渡片段（E1→E2）→ 播放片段（正向/倒放）后进入目标静态帧
  兜底：无片段（跨表情档）→ 80~120ms 交叉淡化（两帧已对齐，无重影）
静音：< -50dB 且持续 150ms → 强制回 E0×中性（闭嘴），表情整体归零
自然感：同档位候选帧随机/轮换；静态帧驻留时叠加 ±2% 低频缩放抖动（防"死图感"）
```

### 5.3 参数面板（借鉴 Live2D / Motion LIVE 的 Sensitivity 设计，全部用户可调）

| 参数 | 默认 | 作用 |
|------|------|------|
| 灵敏度 | 1.0 | 能量→嘴档映射斜率（调高=嘴更敏感） |
| 强度 | 1.0 | 整体表情幅度缩放 |
| 过渡时长 | 100ms | 交叉淡化时长（80~200ms） |
| 状态保持 | 100ms | 状态最小停留 |
| 静音门限 | -50dB | 闭嘴阈值 |
| 切换阈值 | 0.15 档 | 滞回宽度 |

### 5.4 元音口型驱动（共振峰定形状、能量定开合，2026-09-05 接入）

> 来源：用户《修改建议.md》（参考 Project AIRI 口型线：音频拆帧 → 元音判定 → 驱动口型）。
> 边界：元音判定是**共振峰（F1/F2）声学分类**，与能量/F0 同属声学特征层，不涉及语音内容理解，不违反本项目约定。

- **原理**：元音的嘴形由声道共振峰决定。频谱上取 F1（250~1000Hz）与 F2（700~2800Hz）两个主峰，
  在对数频率平面做最近邻分类到五元音参考点：a(850,1250) / e(500,1800) / i(300,2300) / o(500,850) / u(320,800)。
  判定半径外或峰显著度不足（<8dB）→ 判空，回落纯能量驱动。
- **实现**：`core/formants.mjs`（estimateFormants / classifyVowel / createVowelTracker）+ `core/fft.mjs`（Node 离线/测试用；
  浏览器实时直接用 AnalyserNode 的 `getFloatFrequencyData`，零额外计算）。平滑跟踪器复用状态机思想：连续 2 帧确认才切 + 切换后保持 200ms，防清辅音/噪声瞬跳。
- **素材约定**：`manifest.json` 帧加可选字段 `"vowel": "a"|"e"|"i"|"o"|"u"`，slot 表达该元音的开合档。
  元音帧走独立索引（`vowelFrames`），不进中性口型序列。合成示例库 `lib_test_vowel`（每元音 2 档）+ `input/test/test_vowel.wav`（五段双共振峰音）。
- **运行时优先级**：元音帧（能量 ≥ 下限时按元音组内开合选帧）> 表情帧 > 中性能量序列；静音/低能量仍走闭嘴节流。
  库里没有元音帧时整条元音链路不启用，零开销。主页面支持 `?lib=<库名>` 直接指定加载。
- **素材来源（真人/AI 生图二选一）**：① 用 AI 生图工具（即梦/SD/Midjourney 等）以同一人设参考图生成 5 个元音口型图，
  按 manifest 字段放进素材库即用；② 录真人 a/e/i/o/u 长音视频，抽帧后打 vowel 标签建库（建库工具元音模式待做）。

## 六、功能清单（对照商用产品设计，合理不贪多）

**M1（建库工具，离线/本地网页）**
- 导入录制视频，自动抽帧
- 脸对齐 + 统一裁切（可选开关）
- 按记号自动切片打标 + 人工校对界面（删帧/改标签）
- 导出素材库（manifest + frames + clips）

**M2（运行时 MVP，网页）**
- 加载素材库；播放音频文件 / 麦克风输入（两者都要，成本低）
- 能量 → 嘴档状态机（防抖三件套）+ 实时预览（人物 + 波形 + 当前档位指示）
- 静音闭嘴；参数面板（灵敏度/强度/过渡时长/静音门限）

**M3（表情扩展 + 导出）**
- F0 → 表情档（微笑/挑眉）；过渡片段优先播放；候选帧轮换
- 录屏导出：canvas.captureStream() + WebAudio MediaStreamDestination → **单个 MediaRecorder** 录音画合成流（音画同步唯一正确做法，禁止两路分开录再合并）
- 素材库下拉切换（多人物）

**M4（可选）**
- 风格化滤镜"皮"（离线批量处理生成新库）；眨眼/点头微动；API 接入现有网关

## 七、风险与对策（把"大问题"提前堵死）

| # | 风险 | 概率 | 对策 |
|---|------|------|------|
| R9 | **拼接抖动/频闪**（最大风险）：特征高频变化导致帧疯狂切换 | 高 | 状态机防抖三件套：滞回 + 确认 + 状态保持；过渡片段优先 |
| R10 | **重影**：两帧脸部位置不一致，交叉淡化双重曝光 | 中 | 录制时头不动 + M1 脸对齐（MediaPipe 仿射） |
| R11 | **素材覆盖度不足**：某组合没录到 → 运行时无素材 | 中 | 录制脚本强制覆盖 12 组合（第三节 8 段脚本）；每组合备 2~3 候选帧 |
| R12 | **真人恐怖谷**：真人口型与内容对不上（不做内容理解的固有边界） | 中 | 多档口型 + 过渡片段 + 强度可调；预期管理：节奏对、音素不对（动画级口型，真人级脸） |
| R13 | 素材体积/加载慢 | 低 | 512×512 JPEG q80，约 25 帧 ≈ 1.5MB；按需懒加载 |
| R14 | 录制质量差（手抖/曝光/表情失控） | 中 | 录制 checklist（3.1）；建库校对时删异常帧；不行就重录 |
| R15 | 浏览器兼容 | 低 | 仅需 Canvas 2D + Web Audio，无 WebGL 依赖 |

| 里程碑 | 内容 | 预估 | 状态 |

| M1 | 预处理工具：抽帧/对齐/裁切/切片打标/导出素材库 | 1~1.5 天 | 代码 ✓（真人对齐待样片验证） |
| M2 | 运行时引擎：能量→嘴档状态机 + 文件/麦克风 + 预览 + 参数面板 | 1~2 天 | 代码 ✓（自测通过） |
| M3 | F0 表情档 + 过渡片段 + 候选轮换 + 录屏导出 + 多库切换 | 1~2 天 | 代码 ✓（自测通过） |
| M4 | 可选：滤镜换皮 / 眨眼点头 / API | 按需 | — |

**验收标准（M2 完成时）**
- [ ] 播放任意音频（男/女/老/少、中/英/任意语言），嘴张合节奏与能量明显同步
- [ ] 静音闭嘴，无"一直微张"的假说话感
- [ ] **连续观看 30 秒无可见频闪/跳变/重影**（核心验收项，不过关不进入 M3）
- [ ] 低配机器（4 核 + 集显）浏览器实时 ≥60fps
- [ ] 换一段完全不同的音频，表现依然稳定（不挑内容）

**体验验收（M3 后给用户看）**
- [ ] 第一眼觉得"这个人在说话"，且表情随音调有变化（不只是嘴）
- [ ] 用户确认效果符合"真人级观感、动画级口型"定位
